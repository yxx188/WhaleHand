# 记忆系统

> WhaleHand 最「不像 demo」的部分。目标：让一个无状态的大模型在手机上越做越熟，同时不被自己的错误经验带偏。

## 1. 为什么需要

模型每次决策都是全新的：它不知道上次怎么点开的蓝牙，也不记得哪个按钮点不动。没有记忆，每个任务都要重新摸索——慢、贵、还容易迷路。

## 2. 四层结构

| 层 | 载体 | 生命周期 | 怎么回到模型 |
|---|---|---|---|
| 工作记忆 | prompt 里的 `memory` / `plan` 字段 | 单次任务 | 每一步原样带回 |
| 长期记忆 | `memory.jsonl` | 跨任务，30 天遗忘 | 按当前应用包名召回，最多 24 条 |
| 经验卡片 | `cases.json` | 任务结束复盘生成 | 相似目标召回，最多 3 张 |
| 技能 | `skills.json` | 反复成功提炼 | 目标匹配时注入 |

## 3. 长期记忆：把「模型说自己记住了」变成「系统记账」

每条记录：

```json
{"scope":"com.android.settings","text":"蓝牙开关在「已连接的设备」页面顶部","hits":2,"updatedAt":1794...,"ep":"ep_..."}
```

- `scope`：来源应用包名；跨应用通用的写 `global:` 前缀。
- `hits`：**跨任务**印证次数。同一局里重复写同一条不涨。
- `ep`：哪次任务写的，方便追溯。

等级由**代码**判定，不靠模型自述：

| hits | 等级 | 含义 |
|---|---|---|
| 1 | 假设 | 只是线索 |
| 2 | 观察 | 两次任务对得上 |
| 3+ | 已验证 | 三次跨任务印证，可以当证据 |

注入时带上等级标签，prompt 里明确告诉模型：**只有「已验证」能当证据，假设只能当线索**。这让模型不会把一次偶然成功当成真理。

维护规则：

- 注入上限 24 条；每条 80 字以内；`hits` 封顶 9。
- 30 天没被命中的条目遗忘；总数上限 200 条。
- 写入前会做清洗（去掉会过期的 id / 坐标 / 编号这类噪声），由代码执行，不靠模型自觉。

## 4. 经验卡片：任务结束后复盘

任务成功结束后，`EpisodeRecorder` 记录的过程交给 `ExperienceStore.learn`：

1. 压缩过程步骤，拼一个复盘 prompt；
2. 模型输出一张卡片：**path**（这条路怎么走） + **pitfall**（哪个坑要避开）；
3. 卡片与既有长期记忆做比对，重合的条目 `hits+1`——这就是「跨任务印证」的来源；
4. 目标相似度用字符 bigram 的 Jaccard 算，≥ 0.15 才召回，最多 3 张；
5. 上限 50 张，旧的淘汰。

卡片只记「路径和坑」，不记坐标——界面改版后坐标必失效，路径思路还能用。

## 5. 技能：把重复路径固化成模板

成功的操作路径在多个任务里反复出现时，`SkillStore` 会把它提炼成技能（出现 3 次提升），上限 30 条。命中目标时直接注入，省掉模型重新摸索的步数。

## 6. 三条设计原则

1. **模型的自述不算证据。** 等级、遗忘、上限、完成判定全由系统掌握。
2. **记忆会污染，所以要能忘。** 30 天遗忘 + 上限 + 分级，防止一条错误经验永久带偏。
3. **记忆是上下文预算的一部分。** 注入条数、字数都有硬上限，不能因为「多给点信息」把 prompt 撑爆。

## 7. 隐私

记忆 / 经验 / 技能都是 App 私有目录里的本地文件，可以随时在「设置 → 数据与工具」里查看、编辑、清空。只有在你主动发起任务 / 聊天时，相关条目才会随请求发给模型服务商。
